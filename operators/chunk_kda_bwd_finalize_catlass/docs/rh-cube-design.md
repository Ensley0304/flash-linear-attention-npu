# rH 转 Cube 候选（尚未实施）

当前 S1 两个 AIV 各读 64 行 h/dh，转 FP32、逐元素乘、按行归约。S0 的 L1 已有两份 BF16 矩阵，可尝试计算小矩阵的对角线，减少 Vector 搬入、Cast 和归约。

将 128 行切成八组，每组计算 `h[16,128] @ dh[16,128]^T`，FP32 累加。仅取 16×16 结果的对角线，恰好对应这 16 行的 rH。总计 524288 FLOPs，是原逐元素乘加的 16 倍；这是用更多 Cube 工作换 Vector 时间，是否划算必须实测。

- S0 原 GEMM 后计算，L0A/B/C 两槽轮换，保留原事件约束。
- h/dh 的 L1 NZ 行跨度仍为 128。不能把切片直接传给按紧凑 16 行推导跨度的 Operands；两个 LoadData 都应按实际 NZ 块跨度 8 读取八个 K 块。
- 八个 FP32 小矩阵写入 relay 176～184 KiB；不扩 workspace。该区域不与现有 S0、S6、S8 输出重叠，旧 work 的 S9 也不读取。
- 现有 S0 ready flag 保证写完再消费。S1 每个 AIV 读取四个小矩阵，以固定对角索引提取 64 个 rH，仍按原方式发布到 relay 153 KiB。
- 新 work 的 S0 只有在旧 work 的 S8 结束后才开始，此时旧 S1 已消费完小矩阵。S9 的 rH 最终驻留区与小矩阵区分离。

实现约束：NZ 切片起点为 `tile * 256` 个 BF16，两个 LoadData 的 repeatTimes=8、srcStride=8、ifTranspose=false；目标各装入一个 16×128 的 L0 operand。Fixpipe 输出 16×16 FP32 ND，每块 1024 B。AIV 的每半片一次读取四块（4096 B），四次 Gather 各提取 16 个值；固定索引是 `i*17*4` 字节，可放在 small[968:984]，与现有 small[936:968] 的 64×64 对角索引分离。仍需用实际 S1 中间量检查布局，不能仅凭这些推导通过验收。

FP32 累加顺序会变，不保证逐位相同。必须先验 S1 七个边界中间量和普通/单核完整算子，再跑八配置两轮 A/B；稳定提速后验原 20 case 七输出。任何精度门禁失败都先定位或撤销，不修改标杆与阈值。P5c 完成验收或撤销后再实施。
