# Stage 11 前一带 16 行实验

基线 `3db5e900` / R2b，目标 B1/H96/T8192/K=V=128、BF16、无 norm/beta 反向约 9 ms；同时复核 8K/16K 八配置。当前主目标约 10.48 ms，需要约 14.1% 改善。本实验不预设单项就能达到目标。

借鉴附件一次处理较多行、复用已消费输入区的做法，不改变两 head 分工和高精度计算。此前直接融合 Stage 9/11、末带 dG 驻留均回退，不重复。此次只对完整 chunk、非 capture、无 norm 的前一带 Stage 11 改成两个 16 行 tile；原先是四个 8 行 tile。后一带、norm 和尾块保持原路径。

## UB 与生命周期（每 AIV，KiB）

| 区域 | 内容及复用顺序 |
| --- | --- |
| [0,88) | 原 q/k/gk、lower mask、小量，仍供下一带使用，不覆盖 |
| [88,120)、[120,152) | 两个独立 32 KiB 槽，各 left/right/dk/dg 四个 FP32 平面，每平面 16×128×4=8 KiB |
| 每槽 left | left 后处理 → 扫描临时区 → 扫描结束后搬入 raw_g |
| 每槽 right | right 后处理 → q 转 FP32 → Gate 导数临时区 → 最后保存 BF16 dk 输出 |
| 每槽 dk | FP32 dk 保存到最终 Cast 完成 |
| 每槽 dg | dG 后处理 → 扫描 → 原地 Gate 反向 → 最终 dG 输出 |
| [152,160) | k 转 FP32；Gate 阶段已死 |
| [160,178) | 原 band 指数与 beta 广播，不覆盖 |
| [178,184) | 原 packed db、sums、rowScale、db 小量 |
| [184,192) | product → Gate 分母 → 参数梯度归约临时区 |

峰值 192 KiB，无额外 L1/L0/workspace；两槽先搬 left/dk/dg，等待 Cube right 后完成两个输入槽。raw_g 延后到 left 扫描临时区死亡后搬入，增加槽内 V→MTE2→V 同步。两个输入槽兼作最终输出槽，每带仅两次迭代、不循环回填；MTE3 完成前不允许下一阶段覆盖。

扫描仍按高八行、低八行分别执行原三步扫描；suffix、dA_log 和 dDt_bias 的原八行归约及累加次序不变。稳定指数、FP32/残差 GEMM、beta 和原生 layout 不变，GM 偏移保留 64 位。收益假设是向量指令和循环同步合批；代价是 raw_g 延后搬运及新增依赖，必须实测。

静态复核：两槽互不覆盖；right 在最后一次 dk 合并后才能转作 q；left 在扫描和 suffix 更新结束后才能覆盖；Gate 导数最后读取后才能写 BF16 dk。所有旧通知数、workspace bank 回压不变，奇数 head 空 owner 协议不变。

验收：九个边界 case 七输出；八配置两轮交替 A/B、20 预热＋20 采样、设备占用和记录数检查。无 norm 四配置每轮须改善 >0.3%；norm 主核指令保持相同且每轮回退不超过 0.3%，否则不保留。通过性能后跑原 20 case、140 输出，FP32/FP64 标杆、种子、CT L1 不变；最后才提交。未通过者归档并恢复 R2b。此门禁不是完整 200×3 或公开入口验收。

## S1b：提前搬入 raw_g

仅在 S1 完成验收后单独测试。compact 路径中，left 在 `product=left-right` 和 `dk+=left` 后就结束使用；kFloat 在 `product*=key` 后也结束使用。将扫描临时区从 left 改到已空闲的 key[152,160) KiB，原始 gate 可在 left 死亡后立即搬入，与余下 dk 计算和扫描重叠，直到 Gate 真正消费时才等 MTE2_V。

搬运前仍用 V_MTE2 确保 left 的读取完成，搬运后的 MTE2_V 各发、收一次；通知总数、输出生命周期及双槽不变。扫描使用两段独立的 key 临时区，仍按原高八行→低八行顺序，不改变加法树。只改 COMPACT=true 分支，norm、尾块和后一带指令应不变。资源和专项验收门禁同 S1。

S1b 已验收并保留。设备 4，同样两轮八配置采集；无 norm 各轮改善 2.63%～2.86%，norm 主核指令与 S1 相同、耗时变化在 -0.123%～+0.091%，通过专项门禁。全八配置均加速门禁仍为 false。
