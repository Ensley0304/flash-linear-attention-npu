# A2 Finalize跨阶段调度实验

目标：B1/H96/T8192/K=V128/BF16、定长BNSD、不带norm和beta反向，主核与归约核的Task Duration之和低于8 ms。基线H14，源码`0080465a`，原验收10.707 ms；每项均重新同条件A/B，不跨批次相减。

当前目标约需减少25%。Vector忙时约7.1 ms，若运算量不变，8 ms要求Vector占比接近89%；这只是必要条件，不是可达性证明。完整模拟器中，局部搬运和同步空隙仍明显；单独删事件、扩大tile已失败。本轮先验证新的重叠关系，不承诺一项就能达到8 ms。

|---|---:|---:|---|---|
| H19，第一带Stage 11延后 | 10.8782 | 10.8785 | 9×7通过 | 持平，不保留 |
| H20，第一带Stage 9/11延后，dG驻留 | 10.7422 | 11.0317 | 9×7通过 | 回退，不保留 |

以上四项八配置双轮均未通过性能门禁，没有进入20case验收。完整H19模拟器三条MIX lane均完成：AIV Vector忙时约95.57 μs，空隙77～78 μs；H14约95.09 μs、空隙75～76 μs。换序没有减少整体空隙。该H2/T256单核组模拟结果不等于8K设备耗时，重叠统计也不能直接相加。

## H19：把第一带Stage 11移到第二带Cube计算期间

每个chunk仍逆序处理行32～63、0～31。一个AIV负责一个head；两个head、两代workspace不变。

| 顺序 | AIV | AIC |
|---|---|---|
| 1 | Stage 7，带32；暂存该带指数 | Stage 8，带32 |
| 2 | Stage 9，带32；消费本带right完成通知 | Stage 10，带32 |
| 3 | Stage 7，带0；发出两次原BAND_READY | 开始Stage 8/10，带0 |
| 4 | Stage 11，带32 | 继续Stage 8/10，带0 |
| 5 | Stage 9，带0；Stage 11，带0 | 完成当前work的Cube部分 |

原顺序是7/9/11带32→7/9/11带0。新顺序仅交换第一带Stage 11与第二带Stage 7；Stage 11仍先带32、后带0，扫描carry和参数累加次序不变。每项GEMM、指数算法、舍入、tile大小不变。

### 数据生命周期

| 数据 | 保存位置 | 写入与最后读取 |
|---|---|---|
| 带32指数，16 KiB FP32 | 当前bank GM[64,80) KiB，原生产路径不用的BF16 lower区 | Stage 7带32写，延后Stage 11带32前读回 |
| 带0指数，16 KiB FP32 | UB[32,48) KiB，原gk区 | Stage 7带0后gk已结束使用；临时复制到此，Stage 11带32后恢复UB[160,176) |
| q/k | 原UB[0,32) KiB | 两带Stage 7/9及第一带8行Stage 11保持原址，无重读 |
| dq_local/left/right | 原workspace各64行 | Cube按start写不相交的32行；延后消费者读取带32，Cube同时写带0 |

GM[64,80)原zV已被Stage 3消费；生产Stage 7只写FP32 lower，capture不启用本实验。该区不与right[96,128)、qPos[128,160)、bkPos[224,256)重叠。现有S5_DONE继续阻止后两work复用当前bank。

UB、L1、L0和workspace峰值不变。每完整chunk/head新增16 KiB GM写、16 KiB GM读，目标合计384 MiB；另有两次16 KiB UB复制。没有H18的q/k/gk重读。

### 同步检查

- 带32原S8_READY/S8_SECOND_READY仍由Stage 9及其后续等待消费。
- 延后前在MTE3消费带32的S10_FIRST_READY和最后BAND_LOADED，保证下一带的GM写回不会越过旧Cube消费；第二带仍通过原ready/free排空后进入延后计算。
- 延后Stage 11使用编译期RESULTS_READY分支，不再消费已用过的两项通知。带0的通知由正常Stage 9/11消费；每个flag仍每带各set/wait一次，没有增加outstanding深度。
- 带0指数复制到已死gk区后，用V→MTE2桥接再读回旧指数，MTE2→V确认完成；恢复一份inputFree供Stage 11入口消费。第一带Stage 11仍8行，输入区不覆盖UB[32,48)。
- 奇数head的空owner仍按旧顺序消费同样次数的通知；不会提前复用GM。尾块、capture和短前缀保留旧路径，仅完整64行生产路径启用。

这是设计与静态生命周期检查通过的候选，设备精度和性能尚待实测。适用原9个边界七输出→八配置双轮A/B→每配置每轮>0.3%才跑原20case七输出。FP32参考、FP64 golden、CT L1和种子不变；失败回退H14。通过后须补采完整时间线，核实第一带Stage 11与第二带Cube确实重叠，再评估剩余8 ms差距。正式全200case及公开入口验收仍单独完成。

H19设备结果：9个边界七输出通过。设备0上八配置双轮未通过性能门禁；目标H14两轮均值10.8782 ms、H19 10.8785 ms，基本持平。带norm部分配置略有改善，16K无norm回退约0.46%～0.65%。不保留、不进入20case。设备4已有其他测试进程，因此本轮两版均重新在空闲设备0采集，不能与设备4旧值直接相减。

## H20：一起延后第一带Stage 9/11，dG留在UB

作为新的完整候选重新对照H14，不保留H19的性能假设。顺序改为：Stage 7带32→Stage 7带0→Stage 9/11带32→Stage 9/11带0。第一带四项Cube完成通知在Stage 7带32后由MTE3消费；延后Stage 9/11使用RESULTS_READY分支，第二带仍按原协议消费通知。

两个Stage 7都结束后，原gk区域UB[32,64) KiB全部空闲：[32,48)保存第二带指数，[48,64)直接接收Stage 9带32的dG_base并原地更新。Stage 9省掉该带dG的GM写回，Stage 11直接消费这块UB数据，省掉对应GM读取。第一带Stage 11仍8行，输入槽[88,128)和运算/输出区[128,160)均不覆盖驻留dG；第二带16行路径原样执行，届时第一带dG已无消费者。

原gk区域必须等两个Stage 7结束后才能改用；不能把此驻留孤立套到原H14顺序。dG的运算、逆序扫描和归约顺序不改。新增指数GM写读32 KiB，与省去dG写读32 KiB抵消；GM总字节不增加，只有指数的两次UB复制。容量和双buffer不变。先进行生命周期/通知计数检查，再按同一性能与精度门禁上板，不提前叠加其它优化。

## H21：最后一带Stage 9→11直接传dG

独立从H14出发，阶段先后不改；重新安排Stage 9/11之间的UB生命周期。最后一带Stage 7结束后，gk已死：Stage 9将两块16行dG直接读到UB[48,64) KiB，原地更新，Stage 11逆序消费，不再经GM写读。第一带和尾块保留原路径。

Stage 11的16行输入槽0原raw_g位于[56,64)，会覆盖驻留dG；把它移到槽1原dG孔洞[112,120)。两个dG输入都取消GM读取，所以此孔洞可用。槽1的raw_g仍在[120,128)。q/k、运算区、gate输出、lower和小量常驻区不变；输入双buffer和输出双buffer都保留。

| 最后一带期间 | UB区间，KiB | 最后读取 |
|---|---|---|
| dG行0～15 | [48,56) | Stage 11第二个tile |
| dG行16～31 | [56,64) | Stage 11第一个tile |
| raw_g行16～31 | [112,120) | Stage 11第一个tile |
| raw_g行0～15 | [120,128) | Stage 11第二个tile |

Stage 9出口的V→MTE2桥接保留，Stage 11入口继续等待输入槽和输出槽。这里只省去16 KiB写回与16 KiB读回，没有UB复制、没有新增GM通信；目标合计少384 MiB。Cube通知、计算和扫描顺序不变。以H14为对照独立执行原性能与精度门禁，不叠加未验收的H20。

## H22：片上保存两带指数，再验证跨带重叠

H20边界九例七输出通过，但两轮目标10.742→11.032 ms，回退约2.7%，不采用。H22作为新的完整候选对照H14，检验能否消除换序产生的GM暂存代价。

三角掩码只含0和1，改用FP16保存在UB[64,72) KiB，逐tile转FP32后仍用原Mul；不改变矩阵数据类型或舍入。Stage 3展开到当时空闲的product区[152,160)，Stage 7展开到lower阶段空闲的[136,140)，两个消费者都保持输入输出双槽。没有采用Select位掩码：官方A2说明该模式另需8 KiB临时空间，不直接套入现有满UB方案。

第一带指数分两半保存在[72,80)、[152,160)，各8 KiB。第二带Stage 7只用[88,152)作算术临时区，不覆盖这两半。第二带完成后，先将其指数保存到已死gk区[32,48)，再把第一带指数恢复到[160,176)，随后执行第一带Stage 9/11；dG驻留[48,64)。最后恢复第二带指数，执行原第二带Stage 9/11。

这样两带指数均在UB，不需要H20的GM指数写读，第一带dG也不经GM。相对H14净少32 KiB GM/head/chunk；新增掩码展开和片上指数复制，是否划算仍须实测。没有增加UB、L1或workspace；通知次数、逆序扫描和参数归约顺序不变。capture/尾块不换序，但共享的0/1掩码改为FP16，仍纳入边界精度门禁。

API核对：[Select官方说明](https://www.hiascend.com/doc_center/source/en/CANNCommunityEdition/850/API/ascendcopapi/atlasascendc_api_07_0070.html)。本候选实际只使用原有Duplicate/Cast/Mul/Adds，避免引入Select额外临时区。

## H23：把rH归约移到Stage 0 Cube

前面换序实验没有稳定收益。本项独立从H14出发，改变单元分工：Stage 1不再重复从GM读取h/dh并逐行归约；Stage 0用已经驻留L1的h/dh计算8个16×16对角块，Stage 5提取其中128个对角元素作为rH。

每块计算`h[16行,:] @ dh[同16行,:].T`，K=128；只需要对角线，不计算完整128×128矩阵。BF16输入、FP32累加，8次MMAD共524288 FLOPs/head/chunk。L0A/B/C继续按block&1双槽，Fixpipe将8 KiB结果写到当前bank的GM[208,216)，这个区间原来仅前512 B保存rH，其余未用。紧邻的dAkk从216 KiB开始，不重叠。

| 数据/事件 | 新生命周期 |
|---|---|
| L1 h/dh | Stage 0原四项GEMM→8个rH块最后一次LoadData；之后才发l1Free预取下一work |
| GM rH块[208,216) | Stage 0 Fixpipe→Stage 5读取；两代workspace及S5_DONE回压不改 |
| UB rH块[88,96) | Stage 5入口等待旧布局释放后读取，Gather完成后复用作原Stage 5输入 |
| 对角索引[85.25,85.75) KiB | 每launch初始化一次，128个uint32字节偏移；不覆盖Stage 7索引和Stage 11状态 |
| rH完成通知 | 仍由Stage 2之后的PIPE_FIX S02_READY覆盖；Stage 5通过已有Stage 3依赖读取 |

Stage 1只准备kE，可更早发送KE_READY。每head/chunk，原h/dh到UB共64 KiB和rH写读1 KiB，改为rH块写读16 KiB，净少49 KiB GM；已有L1 h/dh无需新增读取。新增Cube工作与被移除的Vector工作是否有净收益，上板决定。L1/L0/UB及workspace容量不增加。

这一项改变rH的累加顺序，不声称逐位等价。纯FP32参考、独立FP64 golden、CT L1与种子都不变；九个边界七输出失败即停止，有稳定性能收益后必须原20case七输出全过。capture及不含Stage 5的短前缀保留原rH路径。

H23设备0首两轮性能作废：采集后发现另一测试进程于20:30:57启动，与该轮重叠。原始报告仍保留，不作为收益或验收证据；九个边界七输出通过的精度报告保留。在设备2重新采集同hash库，并重新对照H14。H19～H22的最后一轮结束于20:27:40之前，早于该进程启动。

## H24：同一rH分工，比较32×32对角块

仍对照H14，未把H23视为已验收。只改变rH对角块大小：4个32×32块、K=128，共1048576 FLOPs，结果16 KiB。GM改用[256,272) KiB的WS_DQ_LOCAL；这个位置到Stage 8才写，Stage 5必已读取完成。不能扩展原[208,216)区，因为Stage 6可能并行写入紧邻dAkk。

Stage 5读取到UB[88,104)，Gather后桥接再复用输入槽；索引改为`(row/32)*1024+(row%32)*33`的字节偏移。L0A/B各8 KiB、L0C4 KiB，仍原双槽。L1→L0B逐16列加载，源stride=8个fractal，目的dstGap=1交织成32列；其它GEMM默认路径不变。净少33 KiB GM/head/chunk，比H23多搬16 KiB，但MMAD/Fixpipe和同步发射次数减半，实际取舍由原门禁决定。
