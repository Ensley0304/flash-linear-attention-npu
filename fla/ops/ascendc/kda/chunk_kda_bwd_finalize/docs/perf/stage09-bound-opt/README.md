# Stage 0～9 bound 优化实验

基线 `81907710`，分支 `kda-finalize-a2`。目标为完整 Stage 0～9 至少一个流水占比达到 80%，同时保证精度和耗时不退化。这里仍是私有分阶段入口的开发验证，不代表完整 Finalize、ATK 或 A3 验收。

## 固定条件

A2 Ascend910B3，CANN 9.1.0，设备 3；B=1/H=96/T=8192/K=V=128，主输入 BF16、gate FP32，性能 case 关闭 Q norm。变长切分为 `[0,1,31,64,65,4096,3935,0]`。每组 20 次预热、10 次测量，表中为 Task Duration 中位数；全部候选仍采用一 AIV 一 head。

服务器目录：`/data/wys/kda-finalize-a2-stage9-20261012/bound-opt`。各版本的源码快照、采数/性能库及原始 profiling 保留在该目录；证据中的 `sha256.json` 标识实际产物。部分 msprof 自动导出返回 -9，只有恢复出完整 30 条目标记录的结果才纳入统计，退出码保留在 profile JSON 中。

## 独立实验

| 版本 | 改动 | 定长 μs / Vector | 变长 μs / Vector | 结论 |
| --- | --- | ---: | ---: | --- |
| r2 | 同期原基线 | 7717.281 / 67.65% | 7852.730 / 67.80% | 比较基准 |
| r3 | Stage 9 独立跨带输出槽，增加 UB 复制 | 7790.751 / 69.40% | 8014.783 / 68.60% | 回退，不采用 |
| r4 | 完整 chunk 特化并展开热循环 | 7834.207 / 66.20% | 8032.235 / 65.50% | 回退，不采用 |
| r5 | 收缩展开，仅固定完整 tile 行数 | 7734.483 / 67.85% | 7867.021 / 67.60% | 没有稳定收益 |
| r6 | 三代 raw workspace，提前下一 work 的 Stage 0 | 7829.247 / 66.90% | 7931.341 / 66.90% | 回退，恢复原工作区和调度 |
| r7 | 去掉生产路径的 FP32 dq 诊断写回 | 7820.745 / 67.00% | 7931.201 / 67.00% | 没有收益，恢复写回 |
| r2-control | 原二进制复采 | 7691.097 / 68.05% | 7879.473 / 67.60% | 检查测量波动 |
| r8 | Stage 7 输出按产出次序交替用槽 | 7717.110 / 67.60% | 7830.997 / 67.70% | 单独收益不明显 |
| r2-rebuilt | 原源码在当前目录重新构建 | 7724.272 / 67.60% | 7799.082 / 67.80% | 排除构建目录迁移影响 |
| r9 | r8 上提前 Stage 9 base 搬入和 q/k 转换 | 7580.262 / 69.20% | 7707.279 / 69.10% | 保留到 r11 |
| r10 | 无额外复制的跨带输出驻留 | 7797.482 / 66.40% | 7910.907 / 66.20% | 无收益，不采用 |
| r11 | r9 上跳过全零 tile 的高低位拆分 | 7487.598 / 65.70% | 7570.160 / 65.80% | 最终保留，精度与复采通过 |
| r12 | r11 上将 Stage 7 改用共享 mask 的 repeat 接口 | 7580.312 / 64.10% | 7661.363 / 64.20% | 比 r11 慢，撤回 |

r3 的占比上升但耗时变差，不能算优化成功。r6 将每核 workspace 从 1280 KiB 增为 1760 KiB，24 核从 30 MiB 增为 41.25 MiB，仍未改善耗时，因此没有保留。

## 布局和同步

r9 保留原 192 KiB UB、全部双槽和 GM 布局。Stage 5 的 dq_base/dg_base 先搬入，再等待 Stage 8 raw；resident q/k 的 Cast、对角线广播在等待 raw ready 前执行。Stage 8 ready 的生产和消费次数不变；奇数 head 的空 owner 仍消费原通知。

r10 从 r3 单独改进：Stage 9 的 dq/dg 留在 `[96,112)`、`[120,136)` KiB，BF16 输出在 `[136,144)`。下一带 Stage 7 的 value、operand/rebuilt 使用已结束读取的 raw 区 `[88,96)`、`[112,120)`；指数 `[144,152)`，输出双槽 `[152,160)`、`[184,192)`。两个独立 MTE3_V 事件保护 Stage 9 输出，在下一次 Stage 9 或 chunk 末尾等待。取消 r3 的两次 UB 复制，不增加容量。

r11 只处理确定无效的工作：全零 tile 一次清零两个 BF16 plane；完整有效 tile 不先清零 value；部分有效 tile 保留清零。有效元素的指数、乘法和残差计算顺序保持。

r12 针对模拟器中大量 `MOVEMASK` 等配置指令，Stage 7 算术与 Cast 使用 64-lane Normal mask，组内复用 mask，带末恢复。FP32 连续 repeat stride 为 8 个 32B block，BF16/FP32 转换使用 4/8，最大 repeat 数 32。依据 [CANN 9.1 SetVectorMask](https://www.hiascend.com/document/detail/en/CANNCommunityEdition/910/API/ascendcopapi/docs/en/api/SIMD-API/basic_api/memory_vector_compute/mask_operations/SetVectorMask.md) 和服务器同版本 SDK 的 `isSetMask=false` 接口；不修改公式、舍入、barrier 或 buffer。

## 验证范围

r3 完成 132 次 Stage 9 tails、36 次 Stage 0～8 smoke、44 次性能库 tails 检查。r4～r8 各通过普通 gate、Q norm 开关、奇数 head、空序列和单核多 work 的首轮 smoke；因性能无收益，没有把这些候选作为交付版继续验收。

r9、r11 均完成同样的 212 次检查；r10、r12 通过首轮 smoke，但性能回退，未继续完整模型验收。r11 的四组完整 8K（定长/变长 × Q norm 开关）采数/性能库均与已验证原基线的实际 dq/dv、有效 dg workspace 逐位一致，采数库的完整 capture/trace 也一致。完整模型沿用此前 FP64 验证的输入和 golden 哈希，本轮没有重新生成全流程 FP64 标杆。Host tiling 检查通过，最终 kernel 按仓库格式化。

## 最终结果：80% 未达标

| 同期最终复采 | 定长 μs | 变长 μs | 最大流水占比：定长 / 变长 |
| --- | ---: | ---: | --- |
| 原 r2 重编译基线 | 7711.310 | 7805.193 | Vector 67.7% / 67.8% |
| 最终 r11 | 7483.497 | 7591.663 | Vector 65.4% / 65.2% |

耗时下降约 **2.95% / 2.73%**；去掉无效 Vector 工作后，占比也下降。保留实际加速，不用补回无效计算抬高占比。最终仅修改 Vector 文件：Stage 7 输出槽交替与全零 tile 简化、Stage 9 提前独立搬运/转换；容量、工作区、全部双缓冲、公式和残差精度保持。**至少一项达到 80% 的目标仍未完成。**

模拟器为同一 2-head、192-token、1-core 三 work case，r9/r11 均正常结束且三 lane 完整。以下仅用于调度分析，不能代替完整 8K 硬件耗时或占比：

| 版本 | AIV0 / AIV1 结束时间 μs | 跨核等待中未与 Vector 重叠的区间 μs |
| --- | --- | --- |
| r2 | 91.94 / 92.39 | 2.39 / 2.01 |
| r9 | 88.91 / 89.41 | 1.70 / 1.53 |
| r11 | 85.14 / 85.64 | 2.35 / 2.24 |

等待区间按 `WAIT_FLAG_DEV*` 与 Vector 指令时间区间求差，不等同于可直接删除的耗时。这个短 trace 不支持“仅扩大跨 work 窗口就足以达到 80%”；硬件 r6 也未获益。r11 每个 AIV 仍约有 2.76 万条 Scalar、2195 条 MOVEMASK，r12 尝试降低配置开销却回退，不能仅凭指令数量判断加速。

原始 CSV、每轮检查日志、实际命令、源码差异、产物哈希及模拟器摘要见 [evidence](evidence/)。全部二进制和完整流水留在服务器 `bound-opt/`，默认开发库已恢复为 r11。后续需重新定位片上搬运、指令发射和 Vector 运算之间的空隙，不能将本轮结果标记为 bound 已完成。

源码差异采用零上下文 patch（回放需 `git apply --unidiff-zero` 并指定对应基线文件）；模拟器日志仅收录末尾摘要并清理行尾空格，完整日志保留在服务器。
