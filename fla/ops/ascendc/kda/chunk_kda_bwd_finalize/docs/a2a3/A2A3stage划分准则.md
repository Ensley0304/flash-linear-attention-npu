# A2/A3 Stage 划分准则

适用范围：Ascend A2/A3 训练、推理系列的 DAV_2201 架构。以下是针对原 19 条约束的修改版；“必须”表示正确性或硬件约束，“优先、尽量”表示需要通过性能数据选择的优化方向。

1. **每个逻辑 Stage 只包含 Cube 或 Vector 一类计算。** 搬运、布局准备和同步归属于相应生产或消费阶段；Stage 不等于 kernel launch。同一个混合 kernel 可以包含多个 Stage。

2. **按数据依赖划分 Stage。** 同一 Cube Stage 内的独立矩阵乘不能读取本 Stage 其他矩阵乘刚生成的结果作为输入；`A@B` 的输出再作为下一次矩阵乘的操作数时，划入后续 Stage。同一矩阵输出的多次 MMAD 累加、归约维分块仍属于一次矩阵计算，可以保留在同一 Stage。Vector Stage 内允许连续依赖前面的 Vector 结果。数据就绪以对应生产和搬运完成为准，不以函数返回或 Stage 编号为准。

3. **按 A2/A3 实际容量规划。** 预算为每个 AIC 的 L1 512 KiB、L0A 64 KiB、L0B 64 KiB、L0C 128 KiB，以及每个 AIV 的 UB 192 KiB。两个 AIV 的 UB 必须分别核算，不能合并为一个连续空间。Cube 操作数使用 L1/L0A/L0B，累加结果使用 L0C，Vector 数据使用 UB；实现时通过平台接口确认容量。

4. **Cube → Vector 必须经过 GM。** 路径为 `L0C → Fixpipe → GM → MTE2 → UB`。Cube 结果可以先保留在 GM，Vector 在实际消费时读入，不要求所有已产生的矩阵结果同时占用 UB。UB 使用单缓冲还是双缓冲，由搬运与计算是否重叠决定，不强制每个结果分配两份。

5. **Vector → Vector 优先复用 UB，允许必要的 GM 暂存。** 相邻消费者优先保留片上结果；生命周期过长、跨 AIV 消费或容量不足时，允许 `UB → GM → UB`。跨 Stage 存活并不自动要求两份空间；按实际在途任务数分配。原址更新仅在 API 支持地址重叠且旧值的全部消费者结束后使用。

6. **Vector → Cube 必须经过 GM。** 路径为 `UB → MTE3 → GM → MTE2 → L1 → MTE1 → L0A/L0B`。禁止假设存在 A5 的 UB → L1 直传。UB 不能通过 Fixpipe 写入 L0C；L0C 是矩阵乘累加结果的位置，不是普通输入操作数的目的缓冲。

7. **Cube → 后续 Cube 按精度选择交接路径。** A2/A3 支持 `FP32 L0C → Fixpipe → BF16/FP16 NZ L1`，该路径不能直接保留 FP32。本方案首版 dW/Tza 使用 BF16 NZ 直传；需要保留 FP32 时走 GM，再明确进入后续 MMAD 的 dtype 和转换方式。继续累加同一矩阵输出时可保留 L0C；L0C 本身不能作为下一次矩阵乘的输入操作数。接口依据见 [L1 内存](L1内存.md)。

8. **按峰值存活集合核算全部片上空间。** UB 必须容纳当前处理块的输入、输出、跨 Stage 驻留量、计算临时量、归约临时量、对齐填充及在途 DMA 缓冲。A2/A3 使用常规 Vector API，不能把 A5 VF 内的寄存器临时量默认视为不占 UB。L1、L0A、L0B、L0C 同样分别核算峰值和缓冲份数。每个 GEMM 明确两侧 dtype、物理布局、FP32 累加及实际 MMAD 次数；BF16 高低位两份不能写成“FP32 单份”。

9. **L1 驻留和缓冲份数由复用收益、任务映射及流水深度决定。** 优先驻留后续矩阵乘反复使用的操作数，允许不同阶段复用已释放的区域。单缓冲、双缓冲或更多份数均须对应明确的在途读写，不把“四份”作为固定要求，也不能因启用双缓冲就重复计算常驻共享数据。

10. **尽量减少重复 GM 读取，不将其设为绝对禁令。** 区分硬件必需的 GM 中转、首次读取和真正的重复读取。同一数据分别供 Cube 和 Vector 使用时，可以分别搬入 L1 和 UB。重复读取、长时间驻留及新增 GM 暂存之间，比较传输字节数、片上占用和实际等待时间；方案中列明选择。

11. **UB 可以跨阶段改变语义，但必须满足生命周期结束条件。** 只有所有计算读取和异步 DMA 读取完成后，旧区域才能被新数据覆盖。不能仅凭前一个 Stage 已发出写回、代码执行到了下一行，就复用对应空间。GM workspace 槽位和 L1/L0 缓冲也遵守同样的生产者、消费者生命周期规则。

12. **允许分 tile、分带和必要的多 pass，不要求一次 VF。** A2/A3 使用受支持的 Ascend C Vector API、repeat、mask 和循环完成计算，不直接沿用 A5 RegBase/VF。能全量放入且性能有利时全量处理；否则按容量、复用和流水需求分块。设计必须写明块大小、循环方向和跨块状态；逆向 cumsum 必须传递后缀累加量，归约必须保留部分和。避免只因内存规划不合理而引入多次完整扫描。

13. **独立 Stage 可重叠，但不能无条件共享空间。** 按依赖图和实际调度确定并发区间；并发存活的数据使用不同区域。若要共享区域，必须增加明确的完成等待或调度约束，并计入串行化代价。Cube/Vector 经 GM 交接时，要保证写入完成、读侧可见及槽位复用安全。本方案首版 Stage 12 使用同一 stream 上的独立归约 kernel，以主 kernel 完成作为全局边界；局部核间信号不能代替该边界。

14. **容量不足时允许改变存储和调度方案。** 可以缩小 tile、减少在途缓冲份数、缩短驻留生命周期、将中间量暂存 GM、重复读取原始数据，或拆分阶段/kernel。按预计成本比较，不规定所有冲突只能通过重复读取解决；同时记录新增搬运、同步和计算量。

15. **优先形成有效的 Cube/Vector 重叠，不强求交替编号。** 连续 Cube 或连续 Vector Stage 可以保留，只要由真实依赖、容量或全局归约决定。独立 Vector 工作应安排到能够覆盖 Cube 等待的时间段。不要为了表面交替增加计算、GM 中转或同步；优化目标是缩短关键路径，而不是让阶段名称交替出现。

16. **减少 Vector 重复计算，按收益决定是否驻留。** 多消费者使用的 exp、除法或归约结果优先评估复用；简单且便宜的逐元素结果允许重算，以换取更短的生命周期和更少的 GM 搬运。跨 tile 重算应明确次数和规模，不能为节省少量 UB 而隐含大量重复工作。

17. **预先规划连续、对齐的缓冲区域，避免运行时整理碎片。** 为每个物理缓冲列出固定偏移、大小、布局、缓冲份数、生产者、消费者和可复用时点。优先通过生命周期复用和 tile 选择解决碎片。禁止依靠搬动仍存活的数据来临时腾出连续空间；数学或硬件要求的转置、ND/NZ 转换属于必要布局操作，应单独计入开销，不与碎片整理混为一谈。

18. **同一执行分支内，各 head 使用一致的数据处理和存储策略。** 核数、head 数或尾块差异通过统一的任务映射与尾块规则处理，不采用同形状、同语义数据因 head 编号不同而任意选择 UB 驻留或 GM 暂存的方案。若确需不同策略，必须定义明确的 shape/布局分支、容量依据及完整验证范围。

19. **在正确性和容量满足后，以端到端性能决定 Stage 数量。** 能合并且不会增加峰值占用、GM 读写或等待的相邻 Vector 工作优先合并；具有不同全局同步范围的工作保留必要边界。Stage 数、kernel launch 数分别统计。不得为了减少 Stage 数牺牲数学语义、边界处理、同步正确性或片上容量，也不得把更少 Stage 直接等同于更高性能。
