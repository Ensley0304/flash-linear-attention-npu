# KDA 并行开发集成基线

本快照保存 C64 反向流水优化及其依赖，也保留现有 C32 和泛化实现供后续开发。它不是全规格性能验收完成的版本。基线父提交为 `f2ed09dc9465fcc42e141560407c811e931811c7`。

## 已有验证与限制

- A3 上 `test_c64_pipeline_upstream.py` 调用 fla-org 原测试与断言：96 passed，13 warnings。详见 `evidence/predicate-upstream.log`；不代表全部上游测试均通过。
- C64，BF16，K=V=256，T=65，H=2：三轮保存模式 Finalize 中位数 256.4–257.6 us，公开反向整链 493.9–496.6 us。原 K128 Finalize 为 46.2–47.0 us。
- 同条件 C64 K256 前向仍约 5.43 ms；原 K128 约 42 us。前向性能未达标。
- C64 重算反向仍约 3.41 ms；C32 完整性能目标未达标。
- 未使用 ATK；本快照不宣称完成 A5 或全量双平台 CI。
- evidence 中保留测试包与源文件 SHA256、性能采样明细。源码哈希覆盖记录中的 19 个文件，并非整个源码树。

## 文件所有权

| 窗口 | 所有权 |
| --- | --- |
| 1 | C64 FwdPrepare、FwdFinalize 专属 kernel 与专属 tiling |
| 2 | KDA 使用的共享 FwdH、C64 BwdRecompute；需保护原 GDN 路径 |
| 3 | C32 前向专属实现 |
| 4 | C32 反向专属实现 |
| 5 | 公共 ACLNN 组合入口、公开接口、共享组件、集成测试、验收报告、C64 反向剩余优化 |

当前 C32 前反向共享 `chunk_kda_bwd/op_kernel/arch22/fused32` 和 `internal_ops/kda_fused32`。窗口 3/4 不能按目录独占：开始改动前须向窗口 5 列出具体文件；entry、owner、contract、tiling 和公共服务默认归窗口 5 协调。窗口 1/2 若需改变缓存契约，须同时明确所有消费者的调整。

## 并行开发与验收约束

各窗口从本完整快照建立独立工作区，不能共用可写工作目录。构建产物、安装环境和日志分别隔离；设备由窗口 5 分配，正式性能采集不能与其他负载共用设备。当前 A3 device 14 由集成窗口协调，其他窗口不得直接覆盖既有 venv/OPP。

Python 仅路由，ACLNN 校验；保持 dtype、状态快照、gate 单位、scale 与舍入契约。C32 保存/重算均保持单计算 kernel。以原高性能路径为基线，使用 fla-org 原断言，分别报告通过、失败、跳过、未覆盖。K256 对原 K128 的不超过 5 倍作为同条件验收目标，不推广为所有 shape 的定律；C32 最终须与优化后的 C64 同规格比较。

本次仅推送个人仓 `feat/fla-compat`，未创建主仓分支或 PR。后续窗口以远端本次提交作为共同起点，合入由窗口 5 统一审查。
